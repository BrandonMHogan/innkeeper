# Phase 3 — UI Design Contract

> Visual and interaction contract for the live traffic feed, per-device destination breakdown, and historical/network-wide bandwidth charts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Phase 3 scope: a new `/traffic` (or equivalent) dashboard area — or a new section on `/dashboard` — showing (1) a live SSE-driven feed of active connections + top talkers per device, (2) a per-device historical bandwidth chart over an arbitrary time range, (3) a per-device destination (domain/IP) breakdown list, and (4) a network-wide bandwidth chart with daily/weekly/monthly views. Builds on Phase 1/2's dark theme, spacing/typography scale, and component inventory — does not redefine them. This phase introduces **charts** to the codebase for the first time; no charting library exists yet.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-svelte (already initialized — unchanged from Phase 2) |
| Preset | `mist` base color (unchanged) |
| Component library | shadcn-svelte components on Bits UI primitives (`bits-ui@2.18.1`, unchanged) |
| Icon library | `@lucide/svelte` (unchanged) |
| Font | `Inter` (unchanged) |
| **Charting library (NEW this phase)** | **LayerChart** (`npm install layerchart`) — Svelte-native charting built on LayerCake + D3, the closest Svelte 5 analog to shadcn/ui's Recharts-based chart blocks. Chosen over hand-rolled D3/SVG because: (a) it ships line/area/bar primitives needed for TRAF-02/TRAF-04 out of the box, (b) it composes with Tailwind utility classes and CSS variables rather than a separate theming system, so it can read the existing `--color-*` tokens directly, (c) it has first-class Svelte 5 runes support, unlike most React-first chart libraries. This is a new npm dependency, not a shadcn registry block — no registry vetting gate applies (see Registry Safety). |

No new shadcn-svelte components are required for the chart surfaces themselves (LayerChart renders raw SVG composed with existing `Card` wrappers), but this phase **does** install one new shadcn-svelte primitive: `tabs` (official registry) for the daily/weekly/monthly view switcher on the network-wide chart, and `scroll-area` (official registry) for the live traffic feed's scrollable connection list. Both are first-party shadcn-svelte components — see Registry Safety.

## Spacing Scale

Inherited from Phase 1/2, unchanged (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding, sparkline-to-value gaps |
| sm | 8px | Tight element spacing, table row internal padding, gap between chart legend items |
| md | 16px | Default element spacing, card padding, gap between chart and its axis labels |
| lg | 24px | Section padding, gap between the live-feed card and the chart cards below it |
| xl | 32px | Page content horizontal padding |
| 2xl | 48px | Major vertical section breaks (e.g. between "Live Traffic" section and "Bandwidth History" section) |
| 3xl | 64px | Page-level top spacing |

**Exceptions for Phase 3:**
- Chart canvas height is fixed per chart type, not on the 8-point scale internally (SVG viewport sizing is a charting-library concern, not a spacing-token concern) — but the **card padding around every chart** (16px) and **gap between stacked chart cards** (24px) still follow the scale.
- Time-range picker / tab-switcher controls (daily/weekly/monthly) use the existing 44×44px minimum touch-target exception already established in Phase 2 for icon-only/compact interactive controls.
- Live feed table rows: minimum row height 40px (not on the 8-point scale, but `>= 40px` is the established minimum tap-friendly row height convention for data-dense table rows; padding inside the row follows `sm` (8px) vertical / `md` (16px) horizontal).

## Typography

Inherited from Phase 1/2, unchanged — no new sizes or weights. Phase 3 maps onto the existing 4 roles:

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|----------------------|
| Body | 14px | 400 (regular) | 1.5 | Live feed table cell values (connection IP/domain, bytes, device name), destination-breakdown list rows, chart axis tick labels, empty/error state body copy |
| Label | 14px | 500 (medium) | 1.4 | Live feed table column headers, chart legend labels, "Top Talkers" / "Destinations" sub-section labels, tab-switcher labels (Daily/Weekly/Monthly) |
| Heading | 20px | 600 (semibold) | 1.2 | Section titles: "Live Traffic", "Bandwidth History", "Network-Wide Bandwidth" |
| Display | 28px | 700 (bold) | 1.15 | Unchanged — page-level heading only, not used within this phase's new sections (those are sub-sections of the existing dashboard/page heading, not new pages with their own Display heading) |

**New numeric/data convention (not a new typographic role — a formatting rule):** bandwidth byte values are always rendered as **human-readable units** (`B`, `KB`, `MB`, `GB`) at Body weight, never raw byte integers — e.g. `1.4 MB`, not `1468006`. This is a copy/formatting rule layered on the existing Body role, not a new size or weight.

Weights used: 400, 500, 600, 700 (no new weights; Fontsource load list unchanged).

## Color

Inherited from Phase 1/2's full palette and 60/30/10 split, unchanged. **No new semantic colors are introduced** — bandwidth/traffic visualization reuses the existing accent (online/positive signal) and muted (secondary/de-emphasized) roles; it does not need its own "traffic" color.

| Role | CSS Variable | Hex | Usage in this phase |
|------|-------------|-----|----------------------|
| Dominant (60%) | `--color-background` | `#0f172a` | Page background, chart canvas background (transparent, inherits page bg) |
| Secondary (30%) | `--color-surface` | `#1e293b` | Live-feed card, chart card containers, destination-breakdown list container |
| Surface border | `--color-border` | `#334155` | Card outlines, chart axis lines, table row dividers |
| Accent (10%) | `--color-accent` | `#10b981` | Reserved-for list below |
| Foreground | `--color-fg` | `#f1f5f9` | Primary text, chart data values on hover/tooltip |
| Muted | `--color-muted` | `#64748b` | Chart axis labels, table secondary text (e.g. protocol/port), empty-state body copy, inactive tab label |
| Destructive | `--color-destructive` | `#ef4444` | Error-state copy/icon only (e.g. SSE connection lost banner) |
| Warning | `--color-warning` | `#f59e0b` | Not used in this phase — no new warning conditions introduced (security-status coloring is Phase 4's concern, not this phase's) |

**Accent (`#10b981`, emerald-500) is reserved exclusively for, in this phase:**
- The **single data series line/area fill** on the network-wide bandwidth chart (one accent-colored line per chart — this phase does not introduce a multi-series chart needing a distinct palette; if a future phase needs multi-device overlay comparison, that is explicitly deferred — see "What This Contract Does NOT Define")
- The active/selected state of the daily/weekly/monthly tab switcher (active tab underline or fill, consistent with Phase 1's existing active-state pattern)
- The "live" pulse indicator dot next to the "Live Traffic" section heading, signaling the SSE connection is active (same visual language as the existing online-status dot on device cards — reusing an established pattern, not inventing a new one)

**Accent and warning are explicitly NOT used for:**
- Per-device bars/rows in the "top talkers" list (these use `--color-fg` for the device name and `--color-muted` for the byte value — color is not used to rank or differentiate talkers; ranking is conveyed by list order + the byte value itself, not color)
- Destination-breakdown rows (domain/IP, byte value — same fg/muted pairing, no per-row coloring)
- Chart gridlines/axes (always `--color-border` or `--color-muted`, never accent)

**Color contrast check:** `--color-muted` (`#64748b`) on `--color-surface` (`#1e293b`) ≈ 4.6:1 — passes WCAG AA, already verified in Phase 2 for the identical pairing reused here for axis labels and secondary table text. `--color-accent` (`#10b981`) on `--color-surface` (`#1e293b`) ≈ 4.4:1 — used here only for non-text elements (chart line/area, tab active indicator, pulse dot), which need only 3:1 per WCAG 1.4.11, so this comfortably passes.

## Copywriting Contract

| Element | Copy | Condition |
|---|---|---|
| Live feed section heading | `Live Traffic` | Always |
| Live feed live-indicator label (visually paired with pulse dot) | `Live` | SSE connection open and receiving updates |
| Live feed stale/disconnected label | `Reconnecting…` | SSE connection dropped — native `EventSource` auto-reconnect is in progress (no manual retry button needed; browser handles reconnection) |
| Top talkers sub-heading | `Top Talkers` | Always, within the live feed card |
| Destinations sub-heading (per device) | `Destinations` | Always, within a device's expanded/detail view |
| Bandwidth history section heading | `Bandwidth History` | Always (per-device chart section) |
| Network-wide chart section heading | `Network-Wide Bandwidth` | Always |
| Time-range tab labels | `Daily` / `Weekly` / `Monthly` | TRAF-04's three required views |
| Primary CTA — none required | n/a | This phase introduces no create/submit action (it is a read-only visualization phase — no "Register"-style primary button exists here) |
| Empty state — live feed, no active connections | Heading: `No active connections` / Body: `Nothing to show right now — this updates automatically as devices send and receive traffic.` | Live feed has connected to SSE successfully but the current snapshot has zero flows |
| Empty state — per-device bandwidth history, no data yet | Heading: `No bandwidth data yet` / Body: `This device hasn't been observed sending or receiving traffic. Data will appear here once it does.` | Device has no `bandwidth_metrics` rows in the selected time range |
| Empty state — destinations, no data yet | Heading: `No destinations recorded` / Body: `This device hasn't been observed talking to anything yet.` | Device has no `traffic_flows` rows |
| Empty state — network-wide chart, no data yet | Heading: `No network activity recorded yet` / Body: `Bandwidth totals will appear here once traffic has been observed.` | No `bandwidth_metrics` rows exist at all (e.g. fresh install before capture has run) |
| Error state — SSE stream fails to establish at all | Heading: `Live traffic feed unavailable` / Body: `Couldn't connect to the live traffic stream. Check that the capture service is running, then refresh the page.` | `EventSource` fires a terminal error (not a transient reconnect — distinguished by repeated failure, not a single drop) |
| Error state — historical chart query fails | Heading: `Couldn't load bandwidth history` / Body: `Something went wrong loading this chart. Try again, or check the server logs if this keeps happening.` | API request for chart data returns non-2xx or times out |
| Destructive actions | None — this phase is read-only (no delete/block/clear actions exist; data is never user-deletable per the "never auto-delete" policy) | n/a |

All copy here is plain, factual, and avoids exclamation/marketing tone, consistent with Phase 1/2's established voice (see prior UI-SPECs' empty/error state copy for the same register).

## Component Inventory (Phase 3)

**Two new shadcn-svelte components installed this phase:** `tabs` (daily/weekly/monthly switcher) and `scroll-area` (live feed connection list, top-talkers list, destination-breakdown list — anywhere a list can grow past a fixed card height). **One new npm dependency:** `layerchart` (charting; see Design System).

| Component | Where | Implementation | Notes |
|-----------|-------|------------------|-------|
| Live indicator | Live Traffic section heading, inline | Small filled dot (8px, `--color-accent`, reuses the existing online-status-dot visual pattern) + `Live` / `Reconnecting…` label (Label role, `--color-fg` / `--color-muted` respectively) | Dot pulses (subtle opacity animation, reuse Phase 1/2's existing CSS animation conventions if any exist, otherwise a simple `@keyframes` opacity pulse) only while connected — no pulse while reconnecting |
| Top talkers list | Within the live-feed `Card`, below the live indicator | Plain ordered list (not a `<table>` — simple repeating rows), each row: device name (Label, `--color-fg`) + current-window byte rate (Body, `--color-muted`), wrapped in `ScrollArea` if it exceeds ~6 visible rows | Sorted descending by rolling-window bytes (per D-12); no manual sort control in this phase — order is server-computed |
| Active connections feed | Within the live-feed `Card`, below top talkers, behind its own sub-heading or tab if both lists are shown together (executor's layout discretion — contract only requires both lists exist and are clearly labeled) | Plain repeating-row list inside `ScrollArea`: device, destination (domain or IP fallback per D-09), port/protocol (`Body`/`--color-muted`), bytes | Updates in place on each SSE push (D-11) — rows re-render, no per-row enter/exit animation required (avoids visual noise on a 5-10s cadence) |
| Per-device bandwidth chart | "Bandwidth History" section, one chart per selected device | LayerChart `AreaChart` or `LineChart` (single accent-colored series), wrapped in `Card`, with a time-range control above it | Time range control is executor's discretion on exact widget (date-range picker, preset buttons, etc.) — contract only requires the user can choose an arbitrary range per TRAF-02, not a specific control type |
| Per-device destination breakdown | "Destinations" sub-section, same device-detail context as the bandwidth chart | Plain repeating-row list (not a chart): registered-domain or IP (Body, `--color-fg`), byte total (Body, `--color-muted`), sorted descending by bytes | Domain grouping per D-10 happens server-side; the list renders pre-grouped rows as-is, no client-side aggregation needed |
| Network-wide bandwidth chart | "Network-Wide Bandwidth" section | LayerChart `BarChart` or `AreaChart` (single accent-colored series, aggregate across all devices), wrapped in `Card`, with `Tabs` (`Daily` / `Weekly` / `Monthly`) above it | One chart instance, re-queried/re-rendered when the active tab changes — not three permanently-mounted charts |
| Empty state | Any of the above when no data exists | Centered text block inside the relevant `Card`: Heading-weight-adjacent but using **Body** size at 500 weight for the empty heading (not full Heading/20px — these are inline empty states inside an existing section, not page-level empty states) + Body/muted for the explanatory line | See Copywriting Contract for exact text per surface |
| Error state | SSE terminal failure or chart query failure | Same layout pattern as empty state, but icon-accompanied (`AlertTriangle` or similar from `@lucide/svelte`, colored `--color-destructive`) and using the error copy above | Distinguish visually from empty state via the icon + destructive-colored heading text — empty state never uses destructive color |

- This phase does not mandate a new top-level route vs. a new section appended to the existing `/dashboard` page — that is left to the planner's discretion based on page-weight/performance considerations (a single page with live SSE + multiple charts may warrant its own `/traffic` route to keep `/dashboard`'s device-grid load fast). The **contract requirement** is: all four section headings above exist somewhere in the app, reachable without a full page reload between them, and the live feed's SSE connection does not get torn down/re-established by unrelated navigation within the traffic area (e.g. switching device selection or chart tab must not close and reopen the `EventSource`).
- Per-device bandwidth history and per-device destinations are co-located (same device-detail view/section) since both are scoped to "the currently selected device" — a single device picker control governs both.
- The live feed (top talkers + active connections) is **not** device-scoped by a picker — it always shows the global snapshot per D-13; any per-device filtering happens client-side as a visual emphasis/highlight, not a separate query.

## Interaction States

| Element | Default | On interaction |
|---|---|---|
| Live indicator dot | Pulsing accent dot, `Live` label | On SSE drop: dot stops pulsing, turns `--color-muted`, label changes to `Reconnecting…`; on terminal failure (no reconnect succeeds after the browser's retry attempts), the live-feed `Card` switches to the Error state described above |
| Device picker (bandwidth history / destinations) | Shows the first device alphabetically or the most-recently-active device (planner/executor discretion — not specified) | Selecting a different device re-queries both the chart and the destinations list together (they share one selection, per Layout above) |
| Time-range control (per-device chart) | Some sensible default range (e.g. last 24h) — exact default left to executor discretion since TRAF-02 only requires "any time range" be selectable, not a specific default | Changing the range re-queries and re-renders the chart; loading state shows the existing `Card` shell with a centered spinner/skeleton (reuse whatever loading-state convention, if any, exists from Phase 1/2 — otherwise a simple centered text "Loading…" in Body/muted is acceptable) |
| Daily/Weekly/Monthly tabs | One tab active (accent underline/fill per Color contract) | Clicking a tab re-queries and re-renders the network-wide chart; standard shadcn-svelte `Tabs` keyboard navigation (arrow keys between tabs, per Bits UI defaults) applies, no custom wiring needed |
| Top talkers / active connections rows | Static display, no hover-interactive affordance required | Rows update in place on each SSE push (5-10s cadence per D-11) — no manual refresh control, no loading spinner between pushes (the existing data simply remains visible until the next push replaces it) |
| Chart hover/tooltip | No tooltip by default | On hover (desktop) or tap (touch), LayerChart's built-in tooltip/crosshair MAY show the exact value at that point — this is a nice-to-have the contract does not mandate as a hard requirement, since neither REQUIREMENTS.md nor CONTEXT.md call for point-level inspection, only "view bandwidth over a time range" at the trend level. If implemented, tooltip text uses Body size, `--color-fg` on a small `--color-surface` popout matching the existing popover surface treatment from Phase 02.1 |

## Accessibility Contract

Inherits Phase 1/2's accessibility contract unchanged, plus:

- **Charts are not the sole means of conveying bandwidth data.** Per WCAG's general guidance against information conveyed by color/visual-only means, every chart in this phase has a textual equivalent reachable without parsing the SVG: the per-device chart sits alongside the numeric destinations list (which already exists per D-10), and the network-wide chart's underlying totals should be available via the existing API response that feeds it (no additional UI element is mandated beyond what's already required for TRAF-02/03/04 — this is a confirmation that the chart augments, never replaces, the data).
- **Live region for the live indicator:** the `Live` / `Reconnecting…` label changes should be wrapped in a polite `aria-live="polite"` region so screen reader users are informed of connection-state changes without the announcement being disruptive (this is a new pattern for the codebase — no prior phase has used `aria-live`, since no prior phase had a live-updating data feed).
- **Live feed updates are not individually announced.** The 5-10s row-level data refresh inside the top-talkers/active-connections lists must NOT be wrapped in `aria-live` — that would cause constant disruptive announcements on every cycle. Only the connection-state change (Live ↔ Reconnecting ↔ Error) is announced, never the data values themselves.
- **Tab switcher (`Tabs`):** keyboard operable via Bits UI's default ARIA tab pattern (`role="tablist"`, arrow-key navigation, `aria-selected`) — no custom wiring required, same as Phase 02.1's reliance on Bits UI primitive defaults for Popover.
- **Color contrast:** all text/background pairings reuse Phase 1/2's already-verified pairings (see Color section above) — no new untested pairing is introduced.
- **Touch targets:** time-range control and tab switcher buttons meet the existing 44×44px minimum hit-area exception already established in Phase 2.

## What This Contract Does NOT Define (Deferred to Future Phases)

| Item | Deferred To |
|------|------------|
| Multi-device overlay/comparison charts (e.g. compare two devices' bandwidth on one chart) | Not in scope — TRAF-02 asks for per-device history, not cross-device comparison; revisit if a future requirement asks for it |
| Security-status coloring on traffic rows (e.g. highlighting a flow to a known-bad IP) | Phase 4 (Security) — this phase's flows/destinations are purely informational, no good/warning/critical signal exists yet |

| Export/download of traffic or bandwidth data (CSV, etc.) | Not requested by TRAF-01..04; no UI element specified |
| Custom/arbitrary date-range picker widget specifics (calendar popover vs. text input vs. preset buttons) | Executor's discretion at implementation time — contract only requires "any time range" be selectable |
| Router-sourced bandwidth visual treatment (once Phase 7's UniFi adapter exists) | Phase 7 — this contract's charts read from the swappable source interface (D-07) but do not need to visually distinguish data origin; if Phase 7 introduces a "source: UniFi vs. passive capture" indicator, that is a Phase 7 UI-SPEC concern |
