    Add `dpkt==1.9.8` to `capture/requirements.txt` (verify exact current version with `pip index versions dpkt` before pinning — use whatever that command reports as latest if it differs).

    Create `capture/traffic_sniff.py` following RESEARCH.md Pattern 1 (aggregated capture loop) and Pattern 2 (passive DNS sniffing) verbatim as the parsing/aggregation core, adapted as follows:

    Module-level: `import socket`, `import time`, `import threading`, `import os`, `import httpx`, `import dpkt`. Define `API_URL = os.environ.get("API_URL", "http://127.0.0.1:8000")` (same env var name as capture.py — do not introduce a second URL env var). Define `FLUSH_INTERVAL = 7` (seconds — midpoint of the locked 5-10s range per D-01/D-11, matching 03-RESEARCH.md Open Question 3's recommendation).

    Define `def _is_wan_bound(src_ip: str, dst_ip: str) -> bool` that returns True only when the packet crosses from a private RFC1918 range to a non-private destination (or vice versa) — use Python's stdlib `ipaddress.ip_address(...).is_private` to classify both src and dst, and return `True` only if exactly one of the two is private (this implements D-03's WAN-only scope: drop any packet where both src and dst are private, since that is LAN-to-LAN traffic).

    Define `def run_traffic_sniff(stop_event: threading.Event)` — the public entry point capture.py will call as a thread target, accepting the *shared* stop_event (not creating its own). Inside: open a raw socket via `socket.socket(socket.AF_PACKET, socket.SOCK_RAW, socket.htons(3))` (ETH_P_ALL); maintain `flows: dict[tuple, int] = {}` keyed by the 5-tuple `(src_mac_str, dst_ip_str, dst_port_or_None, protocol_int)` per D-04, and `dns_cache: dict[str, str] = {}` mapping resolved IP to queried hostname; loop while `not stop_event.is_set()`, calling `sock.recvfrom(65536)` with a short socket timeout (e.g. `sock.settimeout(1.0)`) so the loop can re-check `stop_event` even with no traffic; parse each raw frame with `dpkt.ethernet.Ethernet(raw)`, skip non-IP frames; apply `_is_wan_bound`, skip LAN-only frames; if the packet is UDP with `sport == 53 or dport == 53`, attempt `dpkt.dns.DNS(ip.data.data)` in a try/except `dpkt.dpkt.UnpackError` and populate `dns_cache` from `dns.an` A-records (per RESEARCH.md Pattern 2) — do this check before the flow-aggregation step, since DNS traffic itself does not need to be counted as a "flow" for top-talkers purposes (it is metadata, not user bandwidth); otherwise, build the 5-tuple key from the Ethernet src MAC (format via `:`-joined hex octets, matching capture.py's existing `pkt[ARP].hwsrc`-style string MACs), the IP packet's `dst` (via `socket.inet_ntoa`), the transport-layer `dport` (via `getattr(ip.data, "dport", None)`), and `ip.p` (protocol int); accumulate `flows[key] = flows.get(key, 0) + len(raw)`. Every `FLUSH_INTERVAL` seconds (tracked via `time.monotonic()`), call a `_flush_and_post(flows, dns_cache)` helper that builds the rollup payload (one entry per flow-table key, each including the dns_cache-resolved hostname for that key's dst_ip when present, else `None`) and POSTs it via `httpx.post(f"{API_URL}/api/capture/traffic", json=payload, timeout=5.0)` wrapped in the same `try/except Exception as exc: print(f"[capture] traffic POST failed: {exc}")` swallow-and-continue style already used by `capture.py`'s `on_arp_packet`/`on_dhcp_packet`; then clear `flows` (keep `dns_cache` accumulating across flushes — it is a slowly-growing lookup cache, not per-interval state). The POST payload shape must match: `{"interval_start": <ISO8601 str>, "interval_end": <ISO8601 str>, "flows": [{"src_mac": str, "dst_ip": str, "dst_port": int | None, "protocol": int, "bytes": int, "dst_hostname": str | None}, ...]}` — this exact shape is the contract Plan 03's ingest route Pydantic model will validate against, so do not deviate from these field names.

    Wrap the per-packet parse body in a broad `except Exception` (matching the existing capture.py defensive style for the overall recv loop — a single malformed/truncated frame must never crash the whole sniff thread) that logs via `print` and continues.
  </action>

| capture container → API (`/api/capture/traffic` POST) | Trusted by source (loopback/gateway, enforced server-side in Plan 03's ingest route) — this plan's POST target does not yet validate inbound payloads since the route doesn't exist until Plan 03 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-04 | Denial of Service | traffic_sniff.py's in-memory `flows` dict (unbounded key cardinality on a busy/hostile LAN) | mitigate | FLUSH_INTERVAL (7s) bounds how long any single window's dict can grow before being cleared; Plan 03's ingest route is responsible for bounding payload size server-side (already flagged in 03-RESEARCH.md's Known Threat Patterns table) — this plan's responsibility is bounding the *time* window, not payload size |
| T-03-05 | Tampering | DNS cache poisoning via forged DNS responses from a malicious LAN device | accept | Explicitly accepted per D-08/D-09 — passive-only, best-effort design; a poisoned cache entry only mislabels a domain name (D-09's raw-IP fallback already limits blast radius), it is not a security-control bypass |
