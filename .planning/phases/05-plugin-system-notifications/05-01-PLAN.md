<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Plugin manifest file → backend process | A manifest.json on disk is parsed and trusted at startup; this phase ships only first-party plugins (all code in this repo), but the parser itself must not silently accept malformed/incomplete manifests |
| Plugin module code → backend process | `load_plugin` dynamically imports arbitrary Python from `backend/plugins/<id>/plugin.py` — this is in-process, unsandboxed code execution by design (v1 scope, PDST-02 sandboxing explicitly deferred to v2) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | `manifest.py`'s `discover_manifests`/`load_manifest` | mitigate | Pydantic validation rejects malformed manifests with a raised `ValidationError` rather than silently coercing/dropping fields — a broken manifest is visible at startup, not silently ignored |
| T-05-02 | Denial of Service | `event_bus.py`'s `EventBus.publish` | mitigate | Fire-and-forget `asyncio.create_task` dispatch + per-handler try/except in `_safe_call` ensures one slow/raising subscriber (e.g. a plugin's blocked httpx call) can never block or crash the publishing caller's request path |
| T-05-03 | Denial of Service | `loader.py`'s `PluginLoader` collector task wrapper | mitigate | Every collector invocation is wrapped in the loader's own try/except (not the plugin's) so an unhandled exception in plugin code logs and the loop continues rather than the task silently dying (Pitfall 3) |
| T-05-04 | Elevation of Privilege | `load_plugin`'s dynamic code execution from `backend/plugins/<id>/plugin.py` | accept | v1 ships only first-party, in-repo plugin code (no third-party install path exists yet — that's v2's PDST-01); process-level sandboxing (PDST-02) is explicitly out of scope per REQUIREMENTS.md. Accepted for this phase, not hidden |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | No new package-manager installs this plan — all dependencies (Pydantic, SQLAlchemy, stdlib importlib/asyncio) are already vetted from prior phases |
</threat_model>
