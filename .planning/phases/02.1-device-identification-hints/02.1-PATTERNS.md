### `backend/src/services/identity_inference.py` (new service)

**Analog:** `backend/src/services/identity_resolver.py` (full file, 39 lines — read in full above)

**Core pattern — frozen dataclass result types** (mirrors lines 13-18):
```python

    mac: str
    hostname: str | None
    source: str  # "arp" | "dhcp" | "mdns"
    observed_at: datetime
```
Use this exact shape for `RawSignals` and `InferenceResult` (per RESEARCH.md Architecture Patterns Pattern 1, lines 173-186) — `@dataclass(frozen=True)`, plain typed fields, no methods beyond what's needed.

**Stateless/pure-function convention** (mirrors `HostnameFallbackResolver.resolve()`, lines 27-38):
```python
class HostnameFallbackResolver:
    """D-02/D-03: hostname is the primary identity key, MAC is the fallback.

    Kept pure/stateless (Pitfall 2) — registry-aware identity-key-change
    logic belongs in discovery.py, not here.
    """

    def resolve(self, observation: Observation) -> str:
        hostname = observation.hostname.strip() if observation.hostname else ""
        if hostname:
            return f"host:{hostname.lower()}"
        return f"mac:{observation.mac.lower()}"
```
`identity_inference.infer(identity: DiscoveredIdentity) -> InferenceResult` should follow this exact shape: one pure function (or one small stateless class), no DB session parameter, fully unit-testable by constructing a `DiscoveredIdentity`-like input directly — same testing style `test_identity_resolver.py` already uses.

**Sentinel/exclusion check pattern** (mirrors `MDNS_PLACEHOLDER_MAC` usage, line 10 + its consumers in `discovery.py` lines 90, 105 and `devices.py` line 78):
```python
if observation.mac == MDNS_PLACEHOLDER_MAC:
    ...
```
`infer()` MUST perform the same placeholder check before attempting any vendor lookup (per CONTEXT.md D-07/UI-SPEC's "never show placeholder MAC" rule), plus the new locally-administered (U/L bit) check from RESEARCH.md Pitfall 1 — both checks gate out vendor lookup before calling `AsyncMacLookup.lookup()`.

**Error handling pattern (new — no direct analog, but follows codebase's narrow-except style seen in `devices.py`'s `HTTPException` usage):**
```python
try:
    raw_vendor = await mac_lookup.lookup(identity.mac)
except (VendorNotFoundError, InvalidMacError):
    raw_vendor = None
```
Per RESEARCH.md Pitfall 2 — collapse both "not found" and "invalid" to `None`, never let them propagate to the route layer as a 500.

## Shared Patterns

### Stateless service module convention
**Source:** `backend/src/services/identity_resolver.py` (entire file)
**Apply to:** `identity_inference.py`, `vendor_catalog.py`
Pure functions/frozen dataclasses, no DB session parameters, no I/O beyond what's strictly necessary (here: the in-memory `AsyncMacLookup` data file read). Keeps inference trivially unit-testable without async DB fixtures, mirroring how `identity_resolver.py`'s tests need zero fixtures.

### Sentinel/exclusion-before-lookup convention
**Source:** `MDNS_PLACEHOLDER_MAC` usage across `identity_resolver.py` line 10, `discovery.py` lines 90/105, `devices.py` line 78
**Apply to:** `identity_inference.py`'s `infer()` — must replicate the same "check sentinel before treating as real data" guard for both the placeholder MAC and the new locally-administered-MAC case (RESEARCH.md Pitfall 1), never relying solely on the downstream lookup's exception path for a known-bad input class.

### Inline-style Svelte convention (no Tailwind/CSS modules)
**Source:** `DeviceCard.svelte`, `RegisterDialog.svelte` (entire files — both 100% inline `style="..."` attributes, CSS variables for all colors)
**Apply to:** All new/modified markup in both files this phase — no new `<style>` blocks, no Tailwind utility classes, every color value as `var(--color-*)` matching the existing `theme.css` tokens UI-SPEC references.

### Narrow-exception-to-None degradation
**Source:** Implicit pattern in `devices.py`'s `HTTPException` usage (explicit error → explicit response) and CONTEXT.md/RESEARCH.md Pitfall 2's explicit instruction
**Apply to:** `identity_inference.py`'s `AsyncMacLookup.lookup()` call — `except (VendorNotFoundError, InvalidMacError): return None`, never letting a missing-vendor case escalate to a 500 on `/api/devices/`.

### Dialect-aware upsert (both branches must be touched together)
**Source:** `discovery.py` lines 18-65 (`pg_insert` / `sqlite_insert` parallel branches)
**Apply to:** Extending `upsert_discovered_identity()` for the two new columns — both the Postgres and SQLite branches must be edited in lockstep; this codebase does not share a single dialect-agnostic statement builder for this function, so a one-branch-only edit is an easy mistake to make.
