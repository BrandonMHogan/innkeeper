| Boundary | Description |
|----------|--------------|
| capture container -> /api/capture/{arp,dhcp,mdns} | Loopback-only ingest (existing `_TRUSTED_HOSTS` gate, unchanged this phase) — untrusted raw network data crosses here as `vendor_class_id`/`service_type` strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-02.1-01 | Information Disclosure | `/api/devices/` raw_signals field | accept | Already mitigated by design (per RESEARCH.md Security Domain) — raw_signals surfaces only data already captured/stored by Phase 2's existing pipeline to the same already-authenticated dashboard user; no new data collected, only existing stored data exposed more transparently behind the unchanged `require_auth` gate |
| T-02.1-02 | Tampering | `discovered_identities.mdns_service_type` / `dhcp_vendor_class` columns (untrusted network input via capture ingest) | mitigate | Both new columns declared `String(255)` matching the existing `mdns_events.service_type`/`dhcp_events.vendor_class_id` column lengths (Task 1) — bounds any oversized/malformed string from a hostile LAN device before it reaches the inference engine or the API response |
| T-02.1-03 | Denial of Service | `AsyncMacLookup.lookup()` exception path | mitigate | `VendorNotFoundError`/`InvalidMacError` explicitly caught and degraded to `vendor=None` (Task 1) — an attacker spoofing a malformed MAC cannot crash `/api/devices/` into a 500 |
| T-02.1-04 | Spoofing | Locally-administered (randomized) MAC producing a misleading vendor guess | mitigate | U/L-bit check gates out vendor lookup entirely for randomized MACs (Task 1) — prevents a coincidental OUI-prefix collision from displaying a confidently wrong vendor for a privacy-randomizing device |
| T-02.1-SC | Tampering | `mac-vendor-lookup` PyPI install | accept | RESEARCH.md's Package Legitimacy Audit flagged `[SUS: unknown-downloads]` but approved with documented mitigating evidence (13-release history since 2019, named maintainer repo, pre-existing CLAUDE.md recommendation) — no blocking human-verify checkpoint required per researcher's explicit disposition |
</threat_model>
