## Raw-Signal Transparency (user-initiated addition)

The user requested an info affordance not previously identified as a gray area: a small "i" icon that, on demand, shows the full/raw signal data behind a guess — in case the guess looks wrong or is unclear.

### Interaction mechanism

| Option | Description | Selected |
|--------|-------------|----------|
| Tap/click-to-toggle popover | Works identically on desktop and touch; no hover-only behavior. | ✓ |
| Hover on desktop, tap on touch | Reuse a dual-mode tooltip/popover primitive if shadcn-svelte already supports it. | |
| Always-visible expandable details row | No icon; a "Show details" text toggle inline. | |

**User's choice:** Tap/click-to-toggle popover (recommended option).
**Notes:** Hover-only was explicitly ruled out because the dashboard must work identically from any device on the network, including phones/tablets.

### Info content

| Option | Description | Selected |
|--------|-------------|----------|
| Raw signals only | MAC, raw OUI vendor string, mDNS service type, DHCP vendor class — facts only. | ✓ |
| Raw signals + reasoning | Same, plus a one-line explanation of which signal won and why. | |

**User's choice:** Raw signals only (recommended option).
**Notes:** Captured as CONTEXT.md D-07–D-10. Flagged that this extends beyond what `02.1-UI-SPEC.md` currently defines ("No new icon-only controls are introduced") — UI-SPEC was already approved before this came up, so an amendment or explicit gap acknowledgment is needed before/during planning (D-10).
