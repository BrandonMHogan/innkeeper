<objective>
Build the privileged capture-container side of SEC-01's port scanning: a new `port_scan.py` module wrapping the home-assistant-libs `python-nmap` fork (D-04) for top-1000-port SYN scans, a scan-trigger-listener thread that polls the backend's `/api/capture/pending-scans` (which already returns each pending request's target IP, per Plan 04-02's `Device.last_known_ip` tracking) and runs/POSTs results to `/api/capture/scan`, and a daily-rescan thread that simply pings `/api/capture/queue-daily-scans` on its fixed schedule. Per D-03, the capture container is the only component that ever runs nmap — the backend stays unprivileged, and per D-01/Pitfall 2 the daily-rescan scoping logic lives entirely on the backend (Plan 04-02's `queue-daily-scans` route already queries the `devices` table, never raw observation tables), so this plan's daily loop contains no device-selection logic at all — only a schedule and an HTTP call.

Purpose: Closes SEC-01's actual scan-execution path. Plan 04-02 already built and tested the backend's ingest/poll/queue routes this plan's code calls into; this plan never duplicates that logic.
Output: capture/port_scan.py (new), capture/capture.py (modified — two new threads), capture/requirements.txt (new git dependency, human-verified), capture/Dockerfile (nmap apt package added).
</objective>
