<objective>
Build the backend half of Phase 2 end-to-end: raw observation models for DHCP and mDNS (extending Phase 1's `ArpEvent` pattern), the `IdentityResolver` fusion seam (D-01/D-02/D-03) behind a swappable interface, the `discovered_identities`/`devices` schema split (D-04 lock-on-register), the discovery orchestration service that resolves observations into identities and handles the registered-device identity-key-change case (Pitfall 2), and the `/api/devices` registry routes (list/register/merge). |----------|-------------|
| Capture container → API (`/api/capture/{arp,dhcp,mdns}`) | Loopback/gateway-trusted only, but payload content (MAC/hostname/IP strings) is attacker-influenceable — a malicious LAN device can send a forged DHCP/mDNS packet with a spoofed hostname |
| Browser → API (`/api/devices/*`) | Untrusted input crosses here — registration/merge payloads; gated by existing session auth |
| API → DB | SQLAlchemy ORM boundary — all writes parameterized, including the dialect-aware upsert |
