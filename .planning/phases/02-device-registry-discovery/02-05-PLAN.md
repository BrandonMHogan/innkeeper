<objective>
Close CR-05 from 02-REVIEW.md: a registered/merged Device whose source DiscoveredIdentity originated from an mDNS-only (placeholder-MAC) observation can currently be silently hijacked — its identity_key/last_known_mac/last_seen overwritten — by ANY subsequent mDNS observation for ANY OTHER device, because every hostname-bearing mDNS observation shares the same placeholder MAC (`00:00:00:00:00:00`) and `record_observation`'s Device-branch fast path matches on `Device.last_known_mac == observation.mac` with no exclusion for that shared sentinel.

Purpose: This is a device-hijacking data-corruption bug directly undermining DISC-01 (fused multi-source identity must not corrupt unrelated devices) and DISC-02/DISC-04 (a registered device's identity must remain stable and trustworthy once registered — D-04 in 02-CONTEXT.md explicitly requires a registered device's identity to be "locked to that registry row").
Output: A shared `MDNS_PLACEHOLDER_MAC` sentinel constant in `identity_resolver.py` (single source of truth), a guard in `record_observation` that excludes the placeholder MAC from the Device-branch lookup entirely, and a refusal in `register_device`/`merge_device` to ever persist the placeholder into `Device.last_known_mac`. One regression test proves the exact hijack scenario from CR-05 no longer occurs.
</objective>

## Artifacts this phase produces

- **`backend/src/services/identity_resolver.py`** — new module-level constant `MDNS_PLACEHOLDER_MAC = "00:00:00:00:00:00"`, the single shared sentinel value for "this observation carries no real device-specific MAC."
- **`backend/src/routes/capture.py`** — `_MDNS_PLACEHOLDER_MAC` local definition removed; `ingest_mdns` now imports and uses `MDNS_PLACEHOLDER_MAC` from `identity_resolver.py`.
- **`backend/src/services/discovery.py`** — `record_observation`'s Device-branch lookup (`select(Device).where(Device.last_known_mac == observation.mac)`) is skipped entirely when `observation.mac == MDNS_PLACEHOLDER_MAC`; that branch falls straight through to `upsert_discovered_identity` (hostname-keyed) instead.
- **`backend/src/routes/devices.py`** — `register_device` sets `Device.last_known_mac` to `None` (not `identity.mac`) when `identity.mac == MDNS_PLACEHOLDER_MAC`; `merge_device` leaves `Device.last_known_mac` unchanged (does not overwrite with `identity.mac`) when `identity.mac == MDNS_PLACEHOLDER_MAC`.
- **`backend/tests/test_discovery.py`** — new regression test `test_placeholder_mac_observation_does_not_hijack_registered_device` proving the exact CR-05 scenario is closed.
- **`backend/tests/test_devices.py`** — new regression tests proving `register_device`/`merge_device` never persist the placeholder MAC into `Device.last_known_mac`.
