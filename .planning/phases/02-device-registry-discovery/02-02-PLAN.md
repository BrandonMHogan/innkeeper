<objective>
Extend Phase 1's capture container (already running `network_mode: host` with `CAP_NET_RAW`/`CAP_NET_ADMIN`) with a second Scapy sniffer for passive DHCP/BOOTP observation and an `AsyncZeroconf` mDNS browser, both POSTing to the `/api/capture/dhcp` and `/api/capture/mdns` endpoints built in Plan 01. This makes DISC-01's "ARP, mDNS, and DHCP lease analysis" multi-source discovery real (not just API-testable) — closing the loop from raw LAN packets to the fusion pipeline.

Purpose: Plan 01 proved the fusion/registry backend works against synthetic payloads. This plan makes the discovery pipeline observe real network traffic, which is the actual DISC-01 requirement ("system discovers all devices on the network automatically").
Output: `capture/capture.py` running three concurrent passive observers (ARP, DHCP, mDNS) inside one container, all honoring the existing `stop_event`/SIGTERM shutdown pattern, with `zeroconf` added as a vetted dependency.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| LAN multicast/broadcast traffic → capture container | Untrusted — any device on the LAN can send forged DHCP options or mDNS service records; capture passively observes without authentication |
| capture container → API | Loopback-trusted (Phase 1 D-06 boundary, unchanged) — capture has no DB access and no credentials, only POSTs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-08 | Spoofing | DHCP option 12 (hostname) / mDNS service name forged by a malicious LAN device | accept | Same accepted residual risk as T-02-01 in Plan 01 — passive single-LAN tool, manual-merge-only policy (D-05) is the mitigation at the registry layer, not at capture |
| T-02-09 | Denial of Service | Capture container resource exhaustion from a flood of mDNS Added events or DHCP broadcasts | accept | Low severity — single-host LAN tool; each event is a lightweight POST with a 5s timeout; no unbounded queue growth since each observation triggers an independent fire-and-forget async task |
| T-02-SC | Tampering | npm/pip install of `zeroconf` (the one new third-party package this plan introduces) | mitigate | Blocking human-verify checkpoint (Task 1) before install — confirms package identity against PyPI/GitHub, rejects typosquats, confirms version pin before `requirements.txt` is updated |
</threat_model>
