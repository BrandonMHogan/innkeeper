<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser → API | Untrusted input crosses here — password payloads, session cookie |
| Capture container → API | Semi-trusted (same host, loopback-only) but payload content (MAC/IP strings) is attacker-influenceable if a malicious device sends crafted ARP packets |
| API → DB | SQLAlchemy ORM boundary — all writes parameterized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-01 | Information Disclosure | Session cookie (`backend/src/main.py` SessionMiddleware) | mitigate | `httpOnly` is hardcoded True by Starlette; cannot be exfiltrated via JS — no action needed beyond using SessionMiddleware as specified |
| T-01-02 | Tampering | `/api/auth/login`, `/api/auth/setup` (CSRF) | accept | `SameSite=lax` prevents cross-site form submission; LAN-only single-user tool, ASVS L1 scope note in RESEARCH.md confirms CSRF tokens not required |
| T-01-03 | Information Disclosure | `app_settings.password_hash` | mitigate | `hash_password()` uses `hashlib.scrypt` with random salt — never store plaintext (backend/src/auth.py) |
| T-01-04 | Elevation of Privilege | `/api/auth/login` session fixation | mitigate | `request.session.clear()` called before setting `authenticated=True` (backend/src/routes/auth.py Task 2) |
| T-01-05 | Tampering | `/api/capture/arp` unauthenticated ingest | mitigate | Loopback-only check (`request.client.host` must be 127.0.0.1/::1) returns 403 otherwise (backend/src/routes/capture.py) |
| T-01-06 | Tampering | SQL injection via ARP payload fields | mitigate | SQLAlchemy ORM parameterizes all inserts; no raw SQL string formatting anywhere in routes |
| T-01-07 | Denial of Service | `/api/auth/setup` re-invocation | mitigate | Returns 409 once `setup_complete=True` — cannot be reset via this endpoint (D-08 "hard to bypass") |
</threat_model>
