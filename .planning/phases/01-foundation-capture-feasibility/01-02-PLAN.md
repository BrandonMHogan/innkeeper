## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Capture container ↔ host network namespace | `network_mode: host` shares the host's network stack entirely — broadest trust boundary in the system |
| LAN devices → capture container (passive) | Capture only sniffs; it does not respond to or inject packets in Phase 1 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-11 | Elevation of Privilege | `capture` container escaping to host | mitigate | `cap_add: [NET_RAW, NET_ADMIN]` only — no `--privileged`, no other capabilities added, per PLAT-03 and D-03 (verified by acceptance_criteria grep) |
| T-01-12 | Denial of Service | Unbounded ARP ingest volume from capture to API | accept | Phase 1 is PoC-scale only (D-04); rate limiting and dedup land with the real discovery pipeline in Phase 2 |
| T-01-SC | Tampering | npm/pip installs in Dockerfiles | mitigate | All packages already verified in RESEARCH.md's Package Legitimacy Audit table; no new packages introduced in this plan beyond `scapy`/`httpx` (already audited) |
</threat_model>
