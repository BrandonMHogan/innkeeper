# Phase 1 — UI Design Contract

> Visual and interaction contract for the foundation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Phase 1 scope: `/setup`, `/login`, and an empty protected `/dashboard` shell. This contract establishes the visual foundation all future phases inherit.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn-svelte (recommended — see note) |
| Preset | none — Tailwind CSS v4 with CSS variables |
| Component library | shadcn-svelte (Bits UI primitives) |
| Icon library | Lucide Svelte (`lucide-svelte`) |
| Font | `Inter` (Google Fonts or self-hosted via Fontsource) |

**shadcn-svelte initialization note:**

`components.json` was not found. This is a greenfield SvelteKit 5 + Vite 6 project. `shadcn-svelte` (https://next.shadcn-svelte.com) is the Svelte community port supporting Svelte 5 + Tailwind CSS v4. It is recommended for design consistency across all 8 phases.

To initialize before implementing Phase 1:

```bash
npx shadcn-svelte@next init
```

Select dark theme, CSS variables, and Tailwind CSS v4 when prompted.

If the user chooses not to initialize shadcn-svelte: use Tailwind CSS v4 directly with the color tokens below, and `lucide-svelte` for icons. Mark `Tool: none` when implementing.

## Theme

Dark theme. This is the canonical choice for a self-hosted network monitoring dashboard. Reference category: Grafana, Uptime Kuma, Netdata, Tailscale admin. Light mode is explicitly out of scope for v1.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label padding |
| sm | 8px | Input internal padding (vertical), tight element spacing |
| md | 16px | Default element spacing, card padding, form field gaps |
| lg | 24px | Section padding, card-to-card gap |
| xl | 32px | Page content horizontal padding |
| 2xl | 48px | Vertical centering offset for auth forms |
| 3xl | 64px | Max-width centering block top margin on auth pages |

Exceptions: none for Phase 1.

Auth form card width: fixed at 400px, centered. Minimum page height: 100dvh.

## Typography

Font: `Inter`, loaded via `@fontsource/inter` package (self-hosted, no Google CDN call in production).

Fallback stack: `Inter, ui-sans-serif, system-ui, -apple-system, sans-serif`

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Form labels, helper text, paragraph copy |
| Label | 14px | 500 (medium) | 1.4 | Input labels, nav items, meta text |
| Heading | 20px | 600 (semibold) | 1.2 | Card titles (`h2`), page section headings |
| Display | 28px | 700 (bold) | 1.15 | Page-level heading only — used once per screen |

Weights used: 400, 500, 600, 700. Load only these four weights from Fontsource to minimize bundle.

Note: Label (14px/500) and Body (14px/400) share the same size — they are distinguished by weight only. This is intentional for auth screens.

## Color

Dark theme. All values are CSS custom properties (`--color-*`) on `:root`. Tailwind v4 tokens map to these.

| Role | CSS Variable | Hex (dark default) | Usage |
|------|-------------|-------------------|-------|
| Dominant (60%) | `--color-background` | `#0f1117` | Page background, auth page backdrop |
| Secondary (30%) | `--color-surface` | `#1a1d27` | Auth form card, future sidebar and nav |
| Surface border | `--color-border` | `#2a2d3a` | Card outlines, input borders, dividers |
| Accent (10%) | `--color-accent` | `#3b82f6` | Accent reserved-for list below |
| Accent foreground | `--color-accent-fg` | `#ffffff` | Text on accent-colored buttons only |
| Foreground | `--color-fg` | `#e2e8f0` | Primary body text, headings |
| Muted | `--color-muted` | `#64748b` | Placeholder text, disabled labels, helper copy |
| Destructive | `--color-destructive` | `#ef4444` | Destructive actions only (see below) |
| Destructive foreground | `--color-destructive-fg` | `#ffffff` | Text on destructive buttons only |

**Accent (`#3b82f6`, blue-500) is reserved exclusively for:**
- The primary submit button fill on `/setup` ("Set Password") and `/login` ("Sign In")
- Future: active nav item indicator (Phase 2+)
- Future: link text on error/info messages

**Accent is NOT used for:**
- General interactive states (hover, focus)
- Icons (icons use `--color-muted` or `--color-fg`)
- Borders or dividers

**Focus ring:** `--color-accent` at 50% opacity (`ring-blue-500/50`), 2px solid, 2px offset. Applied to all focusable elements for keyboard accessibility.

**Input background:** `--color-background` (`#0f1117`) — slightly darker than the card surface to create depth.

## Component Inventory (Phase 1)

These are the only components needed in Phase 1. No nav, no sidebar, no data tables.

| Component | Route | shadcn-svelte component | Notes |
|-----------|-------|------------------------|-------|
| Auth card wrapper | `/setup`, `/login` | `Card`, `CardHeader`, `CardContent`, `CardFooter` | 400px wide, centered |
| Password input | `/setup`, `/login` | `Input` (type="password") | Toggle show/hide via eye icon |
| Submit button | `/setup`, `/login` | `Button` (variant="default") | Accent fill, full width |
| Alert / error banner | `/setup`, `/login` | `Alert` (variant="destructive") | Shows above button on error |
| Dashboard shell | `/dashboard` | bare `<main>` element | Empty in Phase 1 — placeholder only |
| Page title (browser tab) | all routes | SvelteKit `<svelte:head>` | See copywriting section |

Password show/hide toggle: `Eye` / `EyeOff` icons from `lucide-svelte`, positioned as an absolutely-placed button inside the input's right padding. Icon size: 16px. Icon color: `--color-muted`. No label on the toggle — icon only with `aria-label="Show password"` / `aria-label="Hide password"`.

## Interaction States

All interactive elements must express exactly these states:

| State | Button | Input |
|-------|--------|-------|
| Default | Accent fill, fg text | Surface bg, border color |
| Hover | Accent at 90% opacity | Border lightens to `--color-fg` at 30% |
| Focus | Accent fill + focus ring | Focus ring, border accent |
| Disabled | 40% opacity, cursor-not-allowed | Not applicable in Phase 1 |
| Loading | Spinner replaces label text (same button size) | Not applicable |
| Error (input) | Not applicable | Border turns `--color-destructive` |

Submit button loading state: spinner is a `Loader2` Lucide icon (16px) with `animate-spin` class. Button text disappears and is replaced by the spinner. Button remains disabled while loading. Never show both spinner and text simultaneously.

## Layout

### Auth pages (`/setup`, `/login`)

```
100dvh centered column
  ┌──── auth card (400px) ────┐
  │  [App name + tagline]     │  ← display heading + muted subtext
  │  ─────────────────────    │
  │  [Form field label]       │
  │  [Input field]            │
  │  [Error alert (if any)]   │
  │  ─────────────────────    │
  │  [Submit button]          │
  └───────────────────────────┘
```

Centering: `display: flex; flex-direction: column; align-items: center; justify-content: center; min-height: 100dvh` on the page wrapper. Background: `--color-background`. No header, no footer, no navigation on auth pages.

### Dashboard shell (`/dashboard`)

Phase 1 dashboard is intentionally empty. It contains only:
- A `<main>` element with `padding: 24px` (lg token)
- A single `<h1>` with the display style: "Dashboard"
- A muted paragraph: "Phase 1 shell — content coming in Phase 2."

No sidebar, no top nav, no breadcrumbs in Phase 1.

## Accessibility Contract

- All form fields have a `<label>` with explicit `for` / `id` binding — no `aria-label` substitutes on visible inputs
- Error alerts are rendered in an `role="alert"` region so screen readers announce them immediately
- Submit button communicates loading state via `aria-busy="true"` while the spinner is active
- Color contrast: `--color-fg` (`#e2e8f0`) on `--color-surface` (`#1a1d27`) = 9.8:1 (WCAG AAA)
- Color contrast: `--color-accent-fg` (`#ffffff`) on `--color-accent` (`#3b82f6`) = 3.0:1 (WCAG AA for large text / UI components)
- Minimum touch target for the submit button: full-width × 44px height
- Tab order on `/setup`: password input → submit button
- Tab order on `/login`: password input → submit button
- The password toggle button (`show/hide`) is reachable via Tab between the input and submit button
