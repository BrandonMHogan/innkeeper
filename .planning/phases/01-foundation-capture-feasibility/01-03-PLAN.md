<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser (any LAN device) → Frontend SPA | Untrusted — any device on the LAN can load the static SPA |
| Frontend SPA → API (cross-origin) | Cookie-bearing fetches; relies on backend CORS allow-list (Plan 01-01/01-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-08 | Information Disclosure | Password input fields | mitigate | `type="password"` masks input by default; show/hide toggle is user-initiated only, no auto-reveal |
| T-01-09 | Tampering | SPA served without SRI/CSP | accept | Self-hosted single-user LAN tool; no third-party CDN scripts loaded (fonts self-hosted via `@fontsource/inter` per RESEARCH.md Don't Hand-Roll table) |
| T-01-10 | Spoofing | Client-side-only auth guard on `/dashboard` | accept | This is a UX redirect, not a security boundary — actual enforcement is server-side `require_auth` (Plan 01-01); documented here so no one mistakes the SvelteKit guard for the real control |
</threat_model>
